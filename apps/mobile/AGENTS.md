# apps/mobile agent rules

- Expo SDK 58 with Expo Router, for iPhone and Android. Native builds run only on EAS: `bunx eas-cli@27.7.2 build --platform <ios|android> --profile <development|development-simulator|preview|production>` (Android: APKs for `development` and `preview`, an AAB for `production`). Never run `expo prebuild` into the repo; `ios/` and `android/` stay out of git.
- Route files in `app/` stay thin: a default export (Expo Router loads it) that reads route params with `useLocalSearchParams` and renders a screen from `src/modules/<module>/presentation/`. Everything under `src/` follows the repo's file-name rules.
- The root layout hands `rpcLink` (`src/platform/rpc/rpc.client.ts`) to `@soonlane/app` with `provideRpcLink` once, at module scope. The API origin is `EXPO_PUBLIC_API_URL`: the EAS build profile sets it, `.env.local` sets it for `bun run start` (see `.env.example`).
- `src/platform/auth/auth.client.ts` is the app's Better Auth client (`@better-auth/expo`'s `expoClient`, never `@soonlane/auth/client`); the oRPC link sends its `getCookie()` header. Its cookie prefix is `EXPO_PUBLIC_AUTH_COOKIE_PREFIX`, which must equal the API's `AUTH_COOKIE_PREFIX`; the app refuses to start without it or `EXPO_PUBLIC_API_URL` (each EAS profile and `.env.local` set both). The session is read with `authClient.useSession()`, whose refreshed cookies reach the Keychain; never log headers, cookies or the client's storage. A route that needs a session goes inside the root layout's `Stack.Protected guard={isSignedIn}`. Sign out only through `signOut` and delete the account only through `deleteUser` from that file, with the id of the user the confirmation named; both run inside its sign-out boundary. On Android `signInWithGoogle` never calls `authClient.signIn.social`: it runs the web hand-off in `android-hand-off.client.ts` and exchanges the code outside the boundary, after checking that no sign-out or deletion started since the tab opened (ADR 0017, SOON-177 update).
- Only `app/+native-intent.tsx` handles incoming links: no code calls `Linking.getInitialURL`, `getLinkingURL`, `useURL`, `useLinkingURL` or `addEventListener('url')`, with one exception: `waitForCode` in `src/platform/auth/android-hand-off.client.ts` listens for `url` only while one Android sign-in is pending, accepts only the build's web origin at exactly `/android/callback` with one well-formed `code`, and stops at the first one, a cancel, a sign-out or the ten-minute wait. `+native-intent.tsx` keeps that link out of routing: the start screen on a cold start, no navigation in an open app. An SDK added later (analytics, crash reporting) runs with deep-link and app-open URL capture off and gets `user.id` at most, never the session object ([ADR 0017](../../docs/decisions/0017-expo-mobile-app.md), SOON-168 update).
- Analytics lives in `src/modules/analytics`: posthog-react-native starts only after the user's yes to the one-time alert or the Settings switch, keeps nothing on the phone, and sends only what the host port `capture` hands it; see the iPhone app section of [docs/analytics.md](../../docs/analytics.md#iphone-app). The key is `EXPO_PUBLIC_POSTHOG_KEY`, and a build without it asks nothing.
- From `@soonlane/app` import only files that need no DOM, TanStack Router or posthog-js; never `@soonlane/ui`, `@soonlane/auth/server` or another app ([ADR 0017](../../docs/decisions/0017-expo-mobile-app.md)).
- Style with `StyleSheet` and `src/tokens.gen.ts`, which `scripts/generate-tokens.ts` writes from `tooling/tailwind-config/tokens.css` and Tailwind's type scale on install, typecheck and start. Never type a color by hand. Text uses the system font. `ActionSheetIOS` only through `showActionSheet` (`modules/shell/presentation/action-sheet.client.ts`), which draws the root layout's `ActionSheet` on Android; `expo-system-ui` makes `userInterfaceStyle: dark` reach Android.
- `metro.config.js` resolves `react`, `react-native` and `@tanstack/react-query` from this app, so Bun's isolated install does not bundle a second copy.
- `app.config.ts` adds to `app.json` what comes from other files: the version from the repo's `version.json`, the splash color from the tokens and Android's one `autoVerify` App Link host from `EXPO_PUBLIC_WEB_URL`, which each EAS profile and `.env.local` set. `assets/` holds the icon and splash image that `bun run images` draws from `apps/web/public/favicon.svg` and the tokens; never edit them by hand. iPhone store builds go through `.github/workflows/mobile.yml` ([docs/release.md](../../docs/release.md#mobile)); Android builds run by hand until the Play Console app exists (SOON-178).
- There is no `build` script: CI covers the app with `bun run check` and `bun run typecheck`. `bunx expo export --platform ios` and `--platform android` are local bundle checks; delete their `dist/` afterwards.
