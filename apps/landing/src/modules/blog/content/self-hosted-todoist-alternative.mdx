Todoist is a hosted service. Your tasks live on Todoist's servers, and you use them through its apps. Some people want their tasks on a server they control, because they already run a home server, their work does not allow outside services, or they want to keep running the app on their own terms.

If that is you, you need an app whose code you can run yourself. Below are three that work like Todoist in some way, and what it takes to run each. I build one of them, Soonlane, so I start with it and say plainly where it is harder to run than the others.

## What to look for

Before you pick one, check these.

- **Sign-in.** Some apps keep their own accounts with passwords. Others need an outside login provider.
- **Moving parts.** One container with a built-in database is quick to set up. Several services and a separate database take more setup and upkeep.
- **Phones.** A server alone gives you no phone app. Check how you will add tasks on your phone.

## Soonlane

Soonlane is an [open source Todoist alternative](/) built around days. It opens on Upcoming, with the week strip at the top, then your Inbox when you have tasks without a date, then Overdue, Today and every day after in one scroll. You get natural date input like `tom` or `fri`, priorities P1 to P4, due times, repeating tasks, subtasks, flat projects, labels and goals that count progress. Each account can also have a private calendar link that shows open tasks in Apple Calendar or any app that reads iCalendar feeds. It has no filters, reminders or sharing.

The code is on [GitHub](https://github.com/Mnigos/soonlane) under AGPL-3.0. You can run it for yourself or for other people. If you run a changed copy for others, the license asks you to offer them your changes.

### What it needs

Soonlane runs as four containers. One Docker Compose file starts Postgres, the API, the web app, and a Caddy proxy that serves the API and web app on a single address. Published images support `amd64` and `arm64`. The API updates the database tables each time it starts.

- **Docker with Compose.** Any machine that runs Docker works, including a home server.
- **A Google OAuth client.** Soonlane itself signs in with Google or a six-digit email code, but the self-host Docker Compose setup wires up only Google sign-in for now. You create a client in Google Cloud and add your callback URL as its redirect.
- **HTTPS for anything except localhost.** Google accepts a plain `http` redirect only on `localhost`. Opening your instance from other devices requires HTTPS in front of it from a reverse proxy or a tunnel.

Configuration goes in one `.env` file containing your URL, a database password, two secrets, and the Google client. The API refuses to start when a value is missing and logs which variable failed. Set `ALLOWED_EMAILS` to your own address so nobody else can sign up. The README on GitHub lists the setup steps and every variable.

A self-hosted copy sends nothing to PostHog.

The Mac app works with your server too. It bakes in the server URLs at build time, so running `APP_URL=https://tasks.example.com API_URL=https://tasks.example.com LANDING_URL=https://soonlane.com bun run package` in `apps/desktop` builds a Mac app pointed at your server instead of soonlane.com.

### Where it is rough

Self-hosting Soonlane is new, so expect a few gaps.

You need a Google Cloud project even for a personal instance because the self-host setup supports only Google sign-in so far. There is no admin page, so `ALLOWED_EMAILS` is the only way to control sign-ups. Four containers are also more to run than one.

If you want a single container with local accounts, Vikunja is the better pick today.

## Vikunja

Vikunja is open source under AGPL-3.0, and its pricing page says self-hosting is free, forever, for any number of users.

You get projects, labels, reminders, repeating tasks and saved filters. Projects can be shown as a list, a kanban board, a Gantt chart or a table. You can share a project with other users, with teams, or with a link that works without an account. It imports from Todoist, Trello and Microsoft To Do, and it has a CalDAV integration, so apps that speak CalDAV can sync with it.

The API and the web interface ship as one binary or one Docker image, `vikunja/vikunja`. The quick start uses the bundled SQLite, so you need no separate database. For more users you can use PostgreSQL, MySQL or MariaDB. There is no default login. You register the first account yourself.

If you would rather not run it, Vikunja Cloud is the paid hosted version, from 4 euros a month for the Personal plan, checked on 24 November 2026.

## Nextcloud Tasks

If you already run Nextcloud, you may not need a new app at all. Nextcloud Tasks is an app inside Nextcloud, open source under AGPL-3.0. You turn it on from the Apps page under Organization.

Tasks have a title, a description, start and due dates, a priority and a status. You can nest subtasks and see smart collections for important, current and upcoming tasks.

It uses CalDAV. Tasks are stored as standard calendar items, so other CalDAV apps can sync them. The project lists Apple Reminders on iPhone and Mac, DAVx5 and Tasks.org on Android, Thunderbird on the desktop, and GNOME and KDE apps on Linux. Those apps give you a way to add tasks on your phone.

Without Nextcloud already running, you would set up a whole Nextcloud server for one list.

## How they compare

## Which one to run

Run Vikunja if you want projects, saved filters and sharing in one binary or one Docker container with a bundled SQLite database.

Use Nextcloud Tasks if you already have Nextcloud and want your tasks in the same apps that hold your calendar.

Run Soonlane if you want a personal day-by-day list without filters or sharing, you are fine with Google sign-in, and you do not mind some setup work. Or skip the server and use the hosted copy at soonlane.com, where the task list is free and integrations, starting with the calendar link, will move to the paid Pro plan.
