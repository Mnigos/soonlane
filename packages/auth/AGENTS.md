# packages/auth agent rules

- `@soonlane/auth/server` (`createAuth`) is server-only and imported only by `apps/api` (`createAuth` only in `modules/identity/infrastructure/better-auth.layer.ts`); `@soonlane/auth/client` is the browser client; the root exports the pure sign-up policy, the account deletion's `GOOGLE_LOGIN_NOT_RENEWED` reason and `readReauth`, the email code's paths, limits and error codes (`email-code.constants.ts`), the signed-in hint's name for a cookie prefix (`getSignedInHintCookie`) and the desktop sign-in contract (loopback address, paths, parameters, PKCE helpers, the bundled page's origin, `AUTH_BASE_PATH`), the iPhone sheet's proxy path (`EXPO_PROXY_PATH`), and the Android hand-off's paths (its pages and its cookie exchange), package and the mobile app's header (`mobile-sign-in.constants.ts`), which `apps/desktop`, `apps/mobile` and the API import too.
- The desktop app's bearer token is the session token signed with the auth secret (`/desktop-sign-in/token`). Keep `bearer` at `requireSignature: true` and without its after hook, which would put the web session's cookie value in a header scripts can read. Before hooks never see a bearer session (Better Auth applies the header only after all of them run), so a hook that looks up the session refuses requests with `authorization`. The one exception is `/delete-user`'s check, which runs the registered bearer hooks itself (`withEndpointHeaders`) and so reads the session the endpoint acts on; never give it a bearer conversion of its own.
- No Effect here: configuration, the database and the logger arrive as arguments.
- Every log argument goes through `redactLogArgument`; Drizzle errors embed session tokens.
- Better Auth reads the client IP only from `CLIENT_IP_HEADER`, which the API's HTTP entry sets. Keep `AUTH_BASE_PATH`, the Google and Todoist redirect URIs (on the API host) and the API's `TRUSTED_ORIGINS` aligned.
- Google only signs in and Todoist (`todoistLink`, a generic OAuth provider) is only linked: `/sign-in/social` refuses Todoist, `/link-social` accepts nothing else, and Todoist's user info is `null` outside a link. Provider tokens are stored encrypted; the endpoints that return them to the browser are disabled, and the API decrypts them with `readStoredOAuthToken`.
- Cookie names come from the caller's `cookiePrefix`; never a fixed name. Return addresses are validated by the `returnAddresses` plugin (`onRequest`, before Better Auth's own checks) against `trustedOrigins` only, plus the mobile app's schemes on `/sign-in/social` (never on `/link-social`), never Better Auth's own list, which also trusts relative paths and the API's origin.
- `/delete-user` passes for a browser, phone or desktop session that an email code started at most 5 minutes ago (`session.emailCodeAt`, while email sign-in is on), or that started with a Google login at most 5 minutes old, read from the newest `auth_time` in the ID tokens on the user's Google account rows (while Google sign-in is on; `account-deletion.handler.ts`); anything else answers `SESSION_EXPIRED` with `reauth`, the methods this user can prove themselves with. When that Google login is older than 5 minutes and the session started more than 60 seconds after it, the answer also carries `reason: GOOGLE_LOGIN_NOT_RENEWED`; never give either a code of its own, which installed app builds would not know. Every Google `/sign-in/social` gets `claims` for `auth_time` from the before hook, never from a client. Never fall back to `freshAge` alone when `auth_time` is missing. No other before hook may change the headers of `/delete-user`, because its check rebuilds the endpoint's headers from the bearer hooks only.
- The mobile app signs in through `@better-auth/expo` (`expoSignIn`), used without its `init`: that trusts `exp://` on `NODE_ENV`, which `bun build` inlines as `development` unless the build sets it. `exp:` is trusted only with `trustExpoGo` (the API passes `APP_ENV=development`). `/expo-authorization-proxy` signs the OAuth state into any browser that opens it, so the before hook lets it through only for one Google authorization URL whose state row is pending, has no `link`, and returns only to an app scheme (`callbackURL`, `newUserURL`, `errorURL`). A callback that redirects to an app scheme sets no browser cookie; the app gets them only in `?cookie=`.
- The Android app signs in through the desktop hand-off's code: `/android/sign-in` on the web mints it with `/desktop-sign-in/code` for the app's challenge and returns it only through the App Link `/android/callback` on its own origin, and the app trades it at `/android-sign-in/exchange` (`androidSignIn`) for a session cookie the Expo client stores. That exchange and `/desktop-sign-in/token` share `startHandOffSession` (consume, verifier, the browser session's `createdAt`) and its rate limit; never give either its own copy of those checks, and never give the desktop app a cookie exchange. The path alone labels the session `mobile` in `sessionCreated`. Never add a cookie-carrying or caller-chosen return to the hand-off.
- Email codes (`emailCodeSignIn`, Better Auth's `emailOTP`) sign in only: every other emailOTP endpoint is in `DISABLED_PATHS`, the guard accepts exactly `{ email, type: 'sign-in' }` and `{ email, otp }`, and the sign-in answer carries no session token. Codes are stored encrypted with `resendStrategy: 'reuse'`, so a resend mails the same code. The per-address cap counts in `rate_limit` under an HMAC of the address before a code is made; never key it by the plain address. Sending always answers success, and on a server with `ALLOWED_EMAILS` an unlisted address without an account gets that answer and no mail. Only the session-create hook (on `/sign-in/email-otp`) and the hand-off (copied from the minting session) set `emailCodeAt`; never accept it from a client.
- A Google sign-in links onto an existing account only when Google vouches for the address (`google-link.handler.ts`: `email_verified` and Gmail or a Workspace `hd`); otherwise `GOOGLE_LINK_REFUSED`.
- Google and email codes are each optional (`google`, `emailCode`); the API refuses to start with neither.
